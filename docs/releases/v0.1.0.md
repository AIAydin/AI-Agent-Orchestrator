These are prepared notes for a possible future Forgeboard v0.1.0 prerelease. They do not indicate
that a `v0.1.0` tag, installer set, or GitHub Release has been published. At publication, the release
workflow prepends the signing status verified from every built platform's `RELEASE-INFO` file and
labels unsigned development artifacts prominently when signing credentials were not configured.

Implemented solo setup is fully UI-driven: install the app, choose safe defaults or use the setup
wizard, and open the deterministic demo without Node.js, pnpm, an account, an API key, or edits to
source/configuration files. The proposed release includes the spatial canvas, local agent execution,
application-managed worktrees, loopback previews, and authoritative primary-checkout Git review,
staging, and commits. Completed writable runs can also be reviewed and committed in their isolated
managed worktrees directly from the UI, without entering a filesystem path or changing a config
file. Broader unchecked product areas remain under active construction in
[`IMPLEMENTATION_CHECKLIST.md`](../../IMPLEMENTATION_CHECKLIST.md).

Data & Privacy includes UI-configured scheduled and changed-data-on-quit SQLite backups with a
per-folder retention target. Users can also browse and create canvas snapshots, restore an exact reviewed snapshot
after native confirmation, and import a portable Forgeboard JSON export in transactional merge or
replace mode. Import revalidates the selected file's exact-byte SHA-256 digest before applying it.
Portable export/import covers settings, projects, canvases, runs, checks, snapshots, and audit
history; repository files and extension source folders remain separate. If the primary database
cannot open safely, startup can restore a user-selected, provenance-checked Forgeboard SQLite backup
through a private staged copy and durable atomic rollback journal. Cancel remains the default, and
newer-schema or unavailable-storage errors quit without offering replacement.

Application update checking is configured under **Settings → Connectivity** with stable,
prerelease, and disabled channels. A check occurs only when the user selects **Check for updates**
and approves the exact native GitHub request. Forgeboard never downloads or installs an update
automatically; after a second native confirmation it can only open a validated release page. These
prepared notes do not claim that such a release page or installer currently exists.

## Planned artifacts

The proposed artifact names are:

- macOS Apple Silicon: `Forgeboard-0.1.0-mac-arm64.dmg`.
- macOS Intel: `Forgeboard-0.1.0-mac-x64.dmg`.
- Windows x64: `Forgeboard-0.1.0-windows-x64-setup.exe`.
- Linux x64: `Forgeboard-0.1.0-linux-x86_64.AppImage` for a portable launch, or
  `forgeboard_0.1.0_amd64.deb` for a system installation.

The proposed release would also include a `SHA256SUMS` file and a `RELEASE-INFO` file with its source
commit and signing status for each platform, plus immutable corresponding-source archives for the
bundled Git toolchain.

## Signing status

Unless signing credentials are configured for the eventual release build, its macOS and Windows
artifacts will be unsigned and their `RELEASE-INFO` files will disclose that status. macOS Gatekeeper
and Windows SmartScreen may then display their normal provenance warnings. Do not disable
operating-system security globally; verify the checksum and source, then use the operating system's
per-app approval only if you trust the build.
